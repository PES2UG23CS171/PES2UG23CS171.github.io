Event Ticketing Platform Microservices

Java · Spring Boot · PostgreSQL · Redis · RabbitMQ · Docker · Kubernetes

An event-ticketing system split into four Spring Boot microservices — web, order API, booking worker and payments — behind an nginx reverse proxy.

  • Checkout modelled as a saga with compensating transactions: ten-minute seat holds under SELECT FOR UPDATE, a SKIP LOCKED reaper for abandoned holds, idempotent consumers, and one global lock ordering that prevents deadlocks
  • RabbitMQ turns bursts into queue depth: a 120-second load test queued 23,600+ bookings while the API kept accepting requests; Redis handles catalogue caching and rate limiting
  • Proved seats never oversell — 20 simultaneous bookings on a 5-seat event across 3 worker replicas leave exactly 5 held; Kubernetes HPA scaled the API from 1 to 6 replicas and back

Order Support Assistant LLM agent

Java 21 · Spring Boot · Spring AI · PostgreSQL + pgvector · Testcontainers

An e-commerce support agent that answers policy questions from a retrieved corpus and acts on real orders — without ever being able to change one on its own.

  • Five tools go through the same governed service layer as the REST API, so the model gets exactly the authorization, validation and optimistic locking an app gets — and no tool takes a customer id it could be talked into
  • State-changing tools return a proposal token, not a change; a compare-and-set gives exactly-once execution under concurrent approvals, with an append-only audit log of every call, denied ones included
  • RAG over pgvector with verifiable numbered citations; 215 tests across unit, Testcontainers integration and HTTP system suites, gated at 93% line coverage in CI

Mini-Redis C++ systems

C++17 · POSIX sockets · kqueue / epoll · CMake

A Redis-compatible in-memory server written from scratch with no third-party dependencies. The stock redis-cli connects unmodified and the official redis-benchmark drives it.

  • Single-threaded event loop on kqueue / epoll speaking RESP2, with pipelining, backpressure and batched replies
  • Hand-written hash table with incremental rehashing, O(1) random sampling and a bit-reversal SCAN cursor that survives resizes; TTL expiry, six eviction policies including LRU, and append-only persistence with three fsync modes
  • 2.52M GETs/sec pipelined and 16 µs unpipelined round trips; 94 tests run on macOS CI under sanitizers

Mega Tic Tac Toe Game AI

Java 21 · Spring Boot 3.5 · WebSockets · vanilla JS

Ultimate tic-tac-toe — nine boards inside one — played online over a shared link, side by side on one device, or against a four-tier computer opponent.

  • The strongest AI is lazy-SMP alpha-beta: every core searches the whole tree and they cooperate through a lock-free transposition table — about 22 million positions and depth 13 in 2.2 s on ten cores, against 1.3 million and depth 11 single-threaded
  • Every 3×3 grid is a nine-bit mask, so win checks are table lookups; a mutable position with an undo stack and incremental Zobrist hashing lets the search run without allocating per node
  • Authoritative online play over plain WebSockets: the server validates every move, the ply count doubles as a sequence number for gap repair, and seats belong to a token so a refresh rejoins the same game
